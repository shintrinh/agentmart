Inventory

Stock on hand for the Blue Bottle Coffee café, with daily usage and days left at current burn rate. Capturing a restock order adds the delivery to stock. “Simulate one day” is a demo helper that advances one day of usage.

Waste — what spoiled

Perishables stocked above their max spoil a little every simulated day (10% of the excess). This is a demo simulation of the carrying cost of overbuying.

Supplier prices

Current prices are Blue Bottle's published retail prices (verified 2026-11-05 — see README); the Aug–Oct 2026 history is illustrative demo data. “Best buy” is the supplier smart restock actually orders from: the alternate wins when it is cheaper and no more than 2 days slower. Creep = up more than 5% in 3 months; drop = down more than 5% — a falling price is a good time to stock up.

Payables — what you owe suppliers

Created when an order is captured, split per supplier. Due date = expected delivery + payment terms (COD = on delivery). Payables only exist for captured orders — an order awaiting approval is not money owed yet.

Forecast — when things run out

Projected from current stock and daily usage (demo forecast, not machine learning). “Order by” is the stock-out date minus the supplier lead time — if it has passed, order now.

Weekly restock plans

Set the schedule once; run it from here or by asking the agent (“run my weekly restock”). Plans run when you ask — there is no background cron on the free demo host.

Subscriptions — weekly restock box

Approve once on PayPal sandbox and the box bills every week. The agent sizes each week's box from burn rate and fulfills it — suspend or cancel any time. (Sandbox billing runs on the real weekly cycle, so the second charge is 7 days out, not visible in this demo.)

Webhook events — what PayPal pushed

PayPal sends async events here (subscription activated/cancelled, invoice paid, order approved, sale completed). Each event is signature-verified before it is trusted; handled events updated the dashboard on their own — no Refresh click needed.

Orders

AG Grid — sort, filter and resize any column. Every row is a real PayPal sandbox order created by the agent or the manual checkout.

Invoices

Create a PayPal invoice from a completed order, then send it to the customer. Invoices are created with the PayPal Invoicing API v2 (sandbox) on NET_30 terms — due date is 30 days after creation. A SENT invoice past its due date shows as overdue; use Send reminder (or ask the agent) to send a PayPal payment reminder.
